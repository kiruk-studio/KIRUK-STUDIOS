# /ism-inviteism

Source of truth: `ideas/ism-inktober/day-08-inviteism.md`. Read it before anything beyond `explain`.

## What it is

> Don't send a message. Send an invitation.

Before you pitch yourself or your brand, learn who they are, then make something just for them — a message, an illustration, a one-person page — blending your brand with their character. They feel invited, not sold to. Template messages feel AI-made and sloppy; this brings trust back.

**Not:** mail-merge with a name swapped in, or a template that "sounds personal."

## Modes (`$ARGUMENTS`)

- **explain** (default) — the ISM in 3 lines plus the rule.
- **invite `<who + what you offer>`** — run the method:
  1. **Their half:** what they care about, how they talk, what they're chasing. Use only what the user tells you or public work the user points to. If thin, ask — don't fill gaps with guesses.
  2. **My half:** the user's brand, story, offer.
  3. **Meeting point:** name the one overlap. If there is none, say so: don't send.
  4. **The invite:** draft the message, and suggest one made-for-them artifact (sketch, page, small thing) that a template could never produce.
  5. Run the "hope you're having a great day" test: delete any line that could go to anyone.
- **review `<draft>`** — mark every line that could be sent to anyone else, then rewrite around the meeting point.
- **page** / **caption** — draft new journal sections or caption variants. Follow `/ism-day` voice rules.

## Rules

- AI can help make it. It can't be the reason it's made. The user adds the real detail.
- Drafts only. Never send anything on the user's behalf.
- Don't compile personal info about the person across sources. Work from what the user gives.
- If it becomes a kiruk client-outreach flow, it stays lab-led (CLAUDE.md non-negotiable #10).
